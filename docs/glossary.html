术语表

课程中出现的技术术语，按主题分组：中文名、英文原文、一两句定义，并链接到首次系统讲解它的页面。

阶段：参考 · 建议 10 分钟

按主题分组。每条给出中文、英文原文、一两句定义，以及系统讲解它的页面。第一次遇到某个词时，可以先回到这里建立最小理解，再顺着链接深入。

基础概念

大语言模型（Large Language Model, LLM）
经过海量文本训练、根据上下文预测下一个 token 的模型。它生成文本，但不直接操作文件或系统。见
智能体（Agent）
让模型在“观察—决策—行动”的循环中调用工具、读取结果并继续决策的系统结构。见
Agent 循环（Agent loop）
读取环境信息、决定下一步、调用工具、观察结果，直到完成或停止的重复过程。见
工作流（Workflow）
沿预定义代码路径执行的多步流程；与由模型动态决定下一步的 Agent 相对。见
提示词（Prompt）
本次发给模型的内容，可以是一句话或一大段；天然是临时的。见
指令（Instruction）
告诉模型“应该怎样做”的稳定内容，通常比单次问题更可复用。见
系统提示词（System prompt）
由客户端在对话开始前注入的高优先级指令，用于设定角色、边界与输出规范。见
词元（Token）
模型处理文本的最小计量单位；可能对应字符、词片段或单词，具体由分词器决定。见
上下文窗口（Context window）
模型一次请求中能处理的 token 总量，包含输入与输出；具体上限因模型而异。见
上下文经济（Context economy）
把有限的上下文预算用于 Agent 真正缺少的信息，省略它已经知道的内容。见
工具调用（Tool use / Function calling）
模型输出结构化的调用请求，由运行环境执行，再把结果回传给模型。见
模型上下文协议（Model Context Protocol, MCP）
连接 AI 应用与外部数据源、工具、工作流的开放标准；Skill 负责“怎么做”，MCP 负责“能连到什么”。见
子代理（Subagent）
由主会话派生的独立会话，执行任务后只把摘要返回主对话，用于隔离长流程。见
个人身份信息（Personally Identifiable Information, PII）
能直接或间接识别个人的信息，例如姓名、证件号、联系方式；技能常需明确禁止输出。见

格式与结构

技能（Skill）
一个包含 SKILL.md 的目录，用于向 Agent 提供专门知识、流程与资源。见
SKILL.md
技能的核心文件，由 YAML frontmatter 与 Markdown 正文组成。见
前置元数据（Frontmatter）
文件开头由两行 --- 包围的 YAML 键值块，提供机器可读的元数据。见
名称字段（name）
必选字段；最长 64 字符，仅小写字母、数字与连字符，必须与父目录名一致。见
描述字段（description）
必选字段；1–1024 字符，说明技能做什么与何时使用，是触发判断的主要依据。见
元数据字段（metadata）
可选的字符串键值映射，用于存放规范之外的附加属性。见
许可证字段（license）
可选字段，指定许可证名称或指向捆绑的许可证文件。见
兼容性字段（compatibility）
可选字段，最长 500 字符，说明目标产品、系统包、网络访问等环境要求。见
允许工具字段（allowed-tools）
可选的空格分隔工具列表，用于预先批准工具；实验性，支持程度因实现而异。见
YAML
一种人类可读的数据序列化格式，用缩进表示层级；Agent Skills 用它编写 frontmatter。见
Markdown
轻量标记语言，用 # 表示标题、- 表示列表、反引号表示代码；用于技能正文。见
正文（Body）
frontmatter 之后的 Markdown 内容，用于写流程、示例与边界情况；无格式限制。见
参考文件（Reference file）
放在 references/ 中、由 Agent 按需读取的文档，用来承载低频细节。见
静态资源（Asset）
放在 assets/ 中的模板、图片、查找表或 schema，通常在执行某一步时使用。见
脚本（Script）
放在 scripts/ 中、由 Agent 调用的可执行代码，适合确定性、重复、易错的逻辑。见
相对路径（Relative path）
相对于技能根目录的路径，例如 references/fields.md；不应使用绝对路径。见
父目录（Parent directory）
直接包含 SKILL.md 的目录；其名称必须与 name 字段完全一致。见

加载与触发

渐进披露（Progressive disclosure）
分三层加载技能：元数据常驻、指令在激活时加载、资源按需加载。见
发现（Discovery）
会话启动时扫描技能目录，只读取各技能的 name 与 description。见
激活（Activation）
任务与描述匹配后，把完整的 SKILL.md 正文读入上下文。见
执行（Execution）
Agent 遵循技能指令，按需运行脚本或读取被引用的文件。见
技能目录（Skill catalog）
客户端向模型披露的可用技能清单，通常包含 name、description 与位置；每项约 50–100 token。见
触发（Trigger）
Agent 判断某个技能与当前任务相关并决定加载它的过程，主要由 description 驱动。见
加载触发（Load trigger）
主文件中写明的条件，告诉 Agent 何时读取某个支持文件；应包含条件、路径与用途。见
近邻负例（Near-miss）
与技能共享关键词或概念、但实际需要其他能力的查询，用于测试描述是否足够精确。见
.agents/skills 目录
跨客户端共享技能的广泛约定路径；规范不规定存放位置，但多数实现会扫描它。见
项目级技能（Project-level skill）
位于项目目录中的技能，通常优先于用户级同名技能。见
用户级技能（User-level skill）
位于用户主目录中的技能，对该用户的所有项目可用，但会被项目级同名技能覆盖。见

设计与评估

真实专长（Real expertise）
来自亲手任务、项目材料或故障记录的领域知识，而非模型的通用训练知识。见
坑点（Gotcha）
违反合理假设的具体环境事实，不写就会导致错误，例如软删除、字段改名、健康检查误报。见
模板（Template）
规定输出结构的样例，比用散文描述格式更可靠；可内联或放入 assets。见
清单（Checklist）
多步流程中的逐项勾选列表，帮助 Agent 跟踪进度、避免跳步。见
验证循环（Validation loop）
执行后运行校验器，失败则读错误、修复、重跑，直到通过才继续。见
计划—校验—执行（Plan-validate-execute）
先产出结构化计划，对照事实源校验，通过后再执行；适合批量或破坏性操作。见
控制校准（Control calibration）
按任务脆弱程度决定指令的具体程度：可逆、可变给自由；不可逆、需一致给规定。见
默认值（Default）
在多种方案中预先选定的一种，替代把所有选项平等列出的菜单。见
连贯单元（Coherent unit）
经常在同一次任务中一起被需要的一组能力，是划分技能范围的依据。见
评估（Eval / Evaluation）
用可重复的用例与检查，判断技能是否触发、输出是否更好，而不是凭印象。见
评估用例（Eval case）
一组提示、预期输出与可选输入文件，用于运行一次可比较的测试。见
断言（Assertion）
对输出应包含或达成什么的可验证陈述，例如“坐标轴有标签”“至少 3 条建议”。见
基线（Baseline）
不用技能或使用上一版本时的结果，用于与当前版本比较。见
通过率（Pass rate）
通过的断言或查询占全部的比例，用于比较配置与轮次。见
触发率（Trigger rate）
同一查询多次运行中技能被调用的比例；用于处理模型行为的随机性。见
训练/验证划分（Train/validation split）
把查询分为调参用与检验用两组；验证集不参与修改决定，用来检测过拟合。见
过拟合（Overfitting）
针对具体测试样例调得过细，换一种说法或新用例就失效。见
基准汇总（Benchmark）
按配置汇总通过率、耗时与 token，并计算差值的记录文件。见
执行轨迹（Execution trace）
Agent 一次运行的完整步骤记录，包括读取、调用、错误与重试；用于定位浪费。见

工具与发布

Token 预算（Token budget）
为某一层内容设定的 token 上限；规范建议正文少于 5000 token、主文件少于 500 行。见
skills-ref
Agent Skills 的参考实现与校验工具，命令为 skills-ref validate ./my-skill。见
幂等性（Idempotency）
同一操作重复执行不会产生额外副作用；Agent 可能重试，脚本应尽量幂等。见
试运行（Dry run）
只预览将要发生的操作而不实际修改，用于破坏性或批量任务。见
退出码（Exit code）
进程结束时返回的数字，用来区分成功与不同失败类型；Agent 据此决定下一步。见
标准输出（stdout）
程序输出主要数据的位置；技能脚本应把结构化结果写到这里。见
标准错误（stderr）
程序输出诊断、进度与错误信息的位置；与 stdout 分离，便于 Agent 解析数据。见
JSON Schema
描述 JSON 数据结构的规范；工具定义常用它声明参数类型与约束。见
光学字符识别（Optical Character Recognition, OCR）
把图片中的文字转换为可编辑文本；扫描版 PDF 提取文本失败时需要，但结果需校验。见
静态站点（Static site）
由预先写好的 HTML、CSS、JS 组成、无需服务端渲染的网站；可直接打开或托管。见
相对链接（Relative link）
相对于当前页面位置的链接，例如 ../glossary.html；项目子路径部署时必须使用。见
GitHub Pages
GitHub 提供的静态站点托管服务，可从仓库分支的根目录或 /docs 目录发布。外部文档
项目子路径（Project subpath）
项目站点位于 https://用户.github.io/仓库名/ 下；根绝对路径会指向错误位置。见
页内目录（Table of contents, TOC）
列出本页章节并跳转到对应锚点的导航块。见
响应式（Responsive）
布局随屏幕宽度调整，保证窄屏（如 360px）仍可阅读与操作。见
无障碍（Accessibility）
让屏幕阅读器、键盘用户等也能使用站点：语义标签、跳转链接、可见焦点等。见
内容分发网络（Content Delivery Network, CDN）
从远程服务器加载脚本、样式或字体的方式；本站不使用，以保证离线可读。见
离线（Offline）
不依赖网络即可打开和阅读；本站所有资源都在本地。见

数据与工程术语

逗号分隔值（Comma-Separated Values, CSV）
用逗号分隔字段的纯文本表格格式；字段含逗号时需用引号包裹。见
制表符分隔值（Tab-Separated Values, TSV）
用制表符分隔字段的表格文本格式，常见于导出数据。见
JSON（JavaScript Object Notation）
用键值对与数组表示结构化数据的文本格式；技能脚本常以它输出结果。见
字符编码（Character encoding）
把字符映射为字节的规则；编码不一致会导致中文乱码或列名异常。见
UTF-8
一种兼容 ASCII 的 Unicode 编码，是跨平台文本的默认选择。见
字节顺序标记（Byte Order Mark, BOM）
文件开头用于标识编码的不可见字节；UTF-8 BOM 会让首个列名带上隐藏字符，读取时应剥离。见
GBK / GB18030
中文环境常见的字符编码；读取 GBK 文件需显式转码，否则按 UTF-8 读取会乱码。见
标准输入（Standard input, stdin）
程序默认的输入流；脚本可通过它接收数据，但不应等待人工键盘输入。见
终端（TTY）
交互式终端设备；Agent 运行脚本时通常没有 TTY，因此不能依赖交互提示。见
持续集成（Continuous Integration, CI）
每次提交自动运行构建、测试或校验的流程；技能校验通常也接入 CI。见
拉取请求（Pull request, PR）
请求把一组代码变更合并进目标分支的机制；评审技能通常以 PR/diff 为输入。见
差异（Diff）
两组代码或文件之间的逐行变化；评审范围通常限定在本次 diff。见
SQL 注入（SQL injection）
把用户输入拼进 SQL 导致执行非预期语句的攻击；防御方式是参数化查询。见
跨站脚本（Cross-Site Scripting, XSS）
把恶意脚本注入页面并在他人浏览器执行的漏洞；前端评审的重点之一。见
跨站请求伪造（Cross-Site Request Forgery, CSRF）
诱导已登录用户在不知情下发出请求的攻击；常通过令牌与同源策略防御。见
静态应用安全测试（Static Application Security Testing, SAST）
不运行程序、通过分析源码发现安全问题的工具；技能应避免重复它已覆盖的问题。见
检索增强生成（Retrieval-Augmented Generation, RAG）
先检索相关文档再交给模型生成的方案；渐进披露不是 RAG，它没有向量检索。见
jq
命令行 JSON 处理工具，常用于读取脚本输出、筛选字段与统计。见
PEP 723
Python 的脚本内联依赖声明规范，用 TOML 块声明依赖，便于自包含脚本。见
WCAG
Web 内容无障碍指南；本站实现基础无障碍项，但未做完整 WCAG 审计。见

加载、校验与上下文管理

加载条件（load condition）
主文件中写明的“什么情况下读取哪个支持文件”的判断条件；应包含可观察条件、路径与用途。见
模型驱动（model-driven activation）
由模型读取技能目录并根据任务与描述判断是否加载，而不是由客户端做关键词匹配。见
用户显式（user-explicit activation）
用户通过斜杠命令、提及或界面按钮直接调用技能，跳过模型的相关性判断。见
内置技能（built-in skills）
随客户端部署产物一起打包、每个会话都可直接使用的技能，通常不依赖用户目录。见
严格校验（strict validation）
按规范逐条检查字段、字符集、长度与目录一致性，不符合即拒绝的校验方式。见
宽松校验（lenient validation）
对不影响功能的问题只警告但仍加载、对无法披露的技能才跳过的实现策略。见
权限白名单（permission allowlisting）
把技能目录加入客户端的允许读取列表，避免每次读取支持文件都触发权限确认。见
结构化包装（structured wrapping）
用可识别的标签或字段包裹技能内容与资源清单，便于模型区分并便于上下文管理。见
资源清单（resource listing）
激活技能时列出可用的 scripts、references、assets 文件，但不预先读取其内容。见
上下文压缩（context compaction）
窗口接近上限时客户端对旧消息做截断或摘要；技能内容应被保护以免静默丢失。见
去重（deduplication）
同一会话中重复激活同一技能时跳过重复注入，避免相同指令在上下文中出现多份。见
子任务（subtask）
交给子代理执行的一段工作；子代理只把结果摘要返回主会话，用于隔离长流程。见

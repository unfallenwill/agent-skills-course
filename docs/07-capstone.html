毕业项目

S5 交付与迁移

毕业项目：设计并发布你自己的高质量 Skill

用一个真实、重复出现的任务完成端到端交付：技能目录、支持文件、触发与输出评估、证据记录。附 100 分评分表与反模式清单。

阶段：S5 交付与迁移 · 建议 240 分钟 · 先修：五个阶段全部完成

毕业项目只有一个要求：解决一个你真实、重复遇到的问题。不是做一个演示，而是交付一个下周还会被使用、能被同事接手、能证明比不用更好的 Skill。

项目简报

选择一个你最近三个月至少做过三次的任务。它应当满足：有稳定的产出、有外行不知道的判断、有可验证的对错。不要选“写一份商业计划书”这种开放任务，也不要选“解释一段代码”这种一次性请求。

项目要素要求
任务真实、重复、有明确产出；来自你的工作，而不是课程虚构
范围能在一次任务中完成一个连贯单元；不与相邻技能重叠
知识至少包含 3 条“外行会做错”的具体事实（字段、命令、阈值、边界）
验证至少有一个可运行的检查或可观察的断言
规模SKILL.md 建议 50–150 行；支持文件按需拆分

交付物

  1. 技能目录：<skill-name>/SKILL.md，frontmatter 合法，name 与目录一致。
  2. 至少一个支持文件：references/、scripts/ 或 assets/，并在主文件写明可观察的加载触发。
  3. 输出评估：evals/evals.json，至少 3 个用例，每个至少 2 条可验证断言。
  4. 触发评估：evals/trigger_queries.json，至少 6 条（建议 20 条），含至少 2 条近邻负例；记录每条 3 次运行结果。
  5. 设计说明：400–600 字，说明范围边界、三个关键取舍、触发策略、验证结论。
  6. 证据：触发记录表、有/无技能的通过率对照、token 与耗时（可用估算），以及至少一条人工评审反馈。
  7. 自评：按下方评分表打分，附一分项理由。

建议节奏（约 6 小时）

阶段时间产出完成标志
M1 选题30 分钟一句话任务描述、3 条“外行会做错”的事实能说出“没有这个技能，Agent 会错在哪”
M2 提取60 分钟知识清单、输入输出样例、失败模式至少有 1 个真实输入与 1 个真实输出
M3 初稿90 分钟SKILL.md + 一个支持文件能在一个真实任务上跑通
M4 评估90 分钟触发表、3 个输出用例、有/无对照有数字，不只是印象
M5 修订与打包60 分钟第二版、设计说明、证据整理至少根据一条失败证据做了修改
M6 同行评审30 分钟评审意见与回应他人能按说明复现你的验证

评分表（100 分）

七个维度来自来源的最佳实践：真实专长、范围、上下文经济、渐进披露、控制校准、触发描述、验证闭环。[源站]（best-practices.md）权重是本课程的判断。[本课程观点]

维度权重1 分（不合格）3 分（合格）5 分（优秀）
真实专长15 正文出现 3 段以上通用最佳实践；删掉这些段落后，任务结果不变 至少 3 条项目特有事实，每条能对应一个真实错误或失败场景 至少 3 条事实可追溯到亲手任务、故障记录或项目材料，并各配一个“不写就会错”的具体场景
范围10 范围无法用一句话说清，或完成一次任务需要加载 3 个以上技能 能用一句话说清边界；至少 3 个任务属于同一连贯单元 描述中写明“不适用”；与相邻技能各有 1 条边界；范围经 1 个真实任务验证
上下文经济15 出现解释 PDF/HTTP/CSV 等常识的段落，或 5 条以上“注意质量”式空话 随机抽 3 段，每段都能说出“不写会错”的具体场景；无重复示例 删减有记录（列出删掉的段落及理由）；主文件 <200 行；多方案处有默认值而非并列选项
渐进披露15 0 个支持文件，或支持文件无加载触发，或存在 A→B→C 引用链 至少 1 个支持文件，且有可观察的加载触发（条件+路径+用途） 至少 2 个支持文件；每个都有“当 X 时读 Y”触发且嵌入流程；主文件 <200 行；无二级引用链
控制校准15 高风险步骤只写“小心操作”，或所有步骤都写成固定命令且无判断标准 不可逆步骤有精确命令；开放步骤有判断标准；至少 1 处默认值 每个不可逆步骤都有精确命令与停止条件；每个开放步骤都有判断标准；至少 3 处使用默认值加明确例外
触发描述15 描述无“何时使用”句，或无场景/关键词，或超过 1024 字符 描述含做什么、何时用、至少 3 种用户说法；不超过 1024 字符 有至少 6 条查询×3 次记录；训练/验证分开；负例含至少 2 条近邻；描述不超过 1024 字符
验证闭环15 无评估用例或断言，或断言无证据、无法复核 至少 3 个用例、每条至少 2 条断言；有/无技能对照 至少 3 个用例、每条至少 2 条断言且 PASS 附证据；有/无对照通过率；记录 token 与耗时；至少 1 条人工反馈并据此修改

通过线：总分 ≥80，且“真实专长”“触发描述”“验证闭环”三个维度均不低于 3 分。任何硬性违规（frontmatter 不合法、name 与目录不一致、描述缺失）直接不通过，需修复后重评。

难度自选

基础

交付 SKILL.md + 一个支持文件；完成 3 个输出用例；触发查询 6 条。

目标分数：80。

进阶

在基础上增加：20 条触发查询、训练/验证划分、两轮迭代、成本对照。

目标分数：88。

挑战

在进阶上增加：同行评审两位、跨客户端验证、脚本带自动化测试、失败模式复盘。

目标分数：95。

反模式清单

逐项检查；命中任意一项，先修复再评分。每条都对应一种常见失败。

  • 通用废话。 “注意质量”“妥善处理错误”“遵循最佳实践”——无法执行，也不提供新信息。
  • 解释模型已知的知识。 用段落介绍 PDF、HTTP、CSV、数据库迁移是什么。
  • 万能技能。 一个技能覆盖读取、转换、分析、部署、运维；描述无法精确触发。
  • 菜单式选项。 列出四个库或三种方法，却不给默认值。
  • 无触发的拆分。 把内容切进 references，只写“详见 references/”。
  • 深链引用。 A 文件让读 B，B 又让读 C；模型容易漏读。
  • 把低频细节放主文件。 字段字典、完整错误码表、历史变更日志占据正文。
  • 高风险步骤模糊。 对删除、迁移、批量发送只写“小心操作”。
  • 交互式脚本。 运行后等待用户输入，Agent 环境下挂起。
  • 失败也返回 0。 脚本出错但退出码为 0，Agent 误以为成功。
  • 把日志写进 stdout。 结构化输出被诊断信息污染，无法解析。
  • 验证靠嘴。 只写“请确保输出正确”，没有命令、断言或期望值。
  • 为通过而改期望。 校验失败后修改断言或期望值，而不是修复问题。
  • 描述堆关键词。 把失败查询里的词直接塞进描述，导致过拟合与误触发。
  • 用验证集调参。 拿验证集失败指导修改，失去泛化检验。
  • 没有负例。 触发查询全是正例，测不出“太宽”。
  • 假评估。 用例只覆盖顺利路径，所有断言无论有无技能都通过。
  • 不可复现。 依赖随机数、当前时间、隐藏状态，却不记录种子与版本。
  • 名称与目录不一致。 本地宽松客户端能加载，换环境或校验时失败。
  • 描述为空或纯口号。 “A powerful tool for documents.” 无法触发任何具体任务。

提交前检查

  • 目录名 = name，符合字符与长度规则。
  • description 1–1024 字符，写清做什么与何时用。
  • SKILL.md 少于 500 行；每个支持文件都有加载触发。
  • 脚本非交互，有 --help、可操作错误与非零退出码。
  • 至少 3 个输出用例、6 条触发查询（建议 20）、3 次运行记录。
  • 有/无技能的通过率对照，以及 token/耗时说明。
  • 设计说明能用 400–600 字讲清三个取舍。
  • 校验通过：skills-ref validate 或本课程脚本。
  • 自评 ≥80，反模式清单逐项排除。

同行评审协议（30 分钟）

  1. 5 分钟：只读 SKILL.md 与描述，写下你认为它何时会触发、解决什么问题。
  2. 10 分钟：按提交说明复现一次验证；记录哪一步无法复现。
  3. 10 分钟：用评分表独立打分，标出与作者自评差距最大的两个维度。
  4. 5 分钟：给出一条“如果只改一处，改哪里”的建议，必须具体到文件与句子。

评审者不应只给分数。最有价值的反馈是：我按你的说明操作时，在哪里卡住了。

完成之后

把技能放进项目的 .agents/skills/，在至少一个真实任务中使用一周。记录每次需要纠正的地方，按用真实执行打磨的方法迭代。毕业项目不是终点，而是你开始维护一套团队技能库的起点。

阶段：参考 · 建议 3 分钟

首页（1 页）

  • 从零到独立设计 Agent Skills一套面向零基础学习者的中文课程：从理解 AI Agent、读懂 Agent Skills 规范，到写出能被可靠触发、可评估、可维护的高质量 Skill。

学习路径（1 页）

  • 学习路径：五个阶段与毕业自检五个阶段从认知准备走到交付与迁移。每一阶段都写清进入状态、离开状态、先修要求、预计时间、组成页面与可观察能力，最后给出毕业自检门禁。

预备知识（5 页）

  • 什么是 Agent：从模型到会动手的系统先建立最基本的心智模型：大语言模型、Agent、Agent 循环，以及 Agent 为什么需要外部知识与流程。
  • 工具调用：Agent 如何真正执行动作模型只产生文本，真正让 Agent 动手的是工具调用（tool use）。理解调用、执行、回传的闭环，以及它与 Skill 的分工。
  • 上下文窗口与 Token：为什么上下文是稀缺资源Token、上下文窗口、注意力分配。理解为什么“把一切都写进提示词”会失败，这是渐进披露存在的根本原因。
  • 提示词、指令与文件式配置从聊天里的提示词，到可版本控制、可审查、可按需加载的指令文件。理解 SKILL.md 这种“文件式配置”的价值。
  • 渐进披露：为什么不能把所有内容一次塞进去用“目录—章节—附录”的类比建立渐进披露直觉，并看清它在 Agent Skills 中对应哪三层、各自花多少 token。

规范与机制（5 页）

  • Skill 的解剖：目录结构与 SKILL.md一个 Skill 就是一个目录，最少只需要一个 SKILL.md。看清必选与可选的每一部分，以及正文该怎么组织。
  • Frontmatter 字段完全指南六个字段的必填性、长度与字符限制，逐条给出合法与非法示例，并解释 name 必须匹配父目录等硬性规则。
  • 渐进披露的工程实现：预算、拆分与加载触发把“渐进披露”落到工程细节：每层多少 token、SKILL.md 的 500 行与 5000 token 预算、如何拆分并写出明确的加载触发。
  • 生命周期：发现、激活、执行从会话启动扫描目录，到模型判断相关并加载全文，再到按需读取资源。同时说明目录约定、冲突覆盖与信任边界。
  • 校验、兼容性与常见坑用 skills-ref 校验、理解严格规范与宽松实现的差别，并逐项排查 name 不匹配、描述缺失、YAML 解析失败等高频问题。

设计方法（6 页）

  • 从真实专长出发，而不是让模型凭空编好 Skill 的共同点是“装着别人不知道的东西”。学习从亲手任务与项目材料中提炼可复用专长。
  • 用真实执行打磨 Skill第一稿几乎总是不够好。用执行轨迹而不只是最终输出来定位三类浪费：指令太虚、指令不适用、选项太多没有默认。
  • 上下文经济：加该加的，删该删的每一句指令都在和对话历史、其他 Skill 争夺注意力。用“没有它 Agent 会做错吗”这条准则做减法，并划出连贯的能力边界。
  • 结构设计：渐进披露与文件组织把长内容移到 references/，并明确告诉 Agent 什么时候读哪个文件。比较“泛泛指路”和“带条件的加载触发”。
  • 控制校准：自由度与规定性的取舍同一个 Skill 里，不同部分需要不同强度的控制。学会按“脆弱性”决定是给自由还是给死命令，并提供默认值而非菜单。
  • 高效指令模式：坑点、模板、清单、验证循环六种可直接套用的结构：Gotchas、输出模板、多步清单、验证循环、计划-校验-执行、打包脚本，以及脚本的代理友好设计。

触发与评估（3 页）

  • 描述字段：Skill 触发的唯一入口description 承担了全部触发判断。掌握四条写作原则，并用“改前/改后”对比看清窄与宽的边界。
  • 触发评估：用查询集调准 description构造 20 条真实查询、划分训练/验证集、每条跑 3 次算触发率，按五步循环改进而不是堆关键词。
  • 输出质量评估：断言、基线与迭代把“看起来还行”变成可比较的证据：写评估用例、跑有/无 Skill 的对照、用断言与证据打分、比较通过率与成本。

动手教程（4 页）

  • 教程 1：20 分钟做出第一个 Skill（roll-dice）从空目录开始，写出一个能真正掷骰子的 Skill：创建目录、写 frontmatter、在 Agent 模式下确认被发现、观察激活与执行。
  • 教程 2：用 references/ 给 Skill 减负从一个 180 行的臃肿 SKILL.md 出发，把风格指南迁移到 references/，写上明确的加载触发，再用行数与实际加载行为验证。
  • 教程 3：打包 scripts/ 并建立验证循环给 Skill 配一个无依赖的 Node.js 脚本，让它输出结构化结果、用退出码报告失败，并把“运行—检查—修复—重跑”写进指令。
  • 教程 4：写 3 个评估用例并调好 description给 changelog-writer 建立最小触发评估：6 条查询、3 次运行、训练/验证划分，按失败类型改描述而不是堆关键词。

实战案例（3 页）

  • 案例 1：PDF 表单批量填写（文档处理）300 份表单、字段名不统一、填错代价高。完整走一遍情境、需求、被否决的方案、SKILL.md、验证方法与失败模式。
  • 案例 2：团队代码评审（代码工作流）用 Skill 固化团队的评审关注点与输出格式，同时避免变成噪声制造机。重点在控制校准与历史 PR 验证。
  • 案例 3：运营 CSV 分析（数据分析）编码不一、日期格式混乱、金额带符号。用默认库、脚本与坑点清单把一次性的分析变成可复现流程。

毕业项目（1 页）

  • 毕业项目：设计并发布你自己的高质量 Skill用一个真实、重复出现的任务完成端到端交付：技能目录、支持文件、触发与输出评估、证据记录。附 100 分评分表与反模式清单。

案例 3：运营 CSV 分析（数据分析）

编码不一、日期格式混乱、金额带符号。用默认库、脚本与坑点清单把一次性的分析变成可复现流程。

阶段：S5 交付与迁移 · 建议 45 分钟 · 先修：S3、S4 完成

数据分析任务看起来最“适合”直接让模型自由发挥，也最容易得到不可复现的结果：这次删了空值，下次填了 0；这次按月，下次按周。案例重点是把默认口径、清洗规则与验证做成可重复的流程。

情境

一家零售公司的运营团队每周收到三份 CSV：门店销售、线上订单、退货记录。文件由不同系统导出：门店文件是 GBK 编码，线上文件带 UTF-8 BOM，退货文件的金额混有人民币符号与千分位逗号，日期列同时存在 2025-03-01 与 01/03/2025。运营同事每周花两小时做同一套汇总，再手工做三张图。

痛点不是“不会算”，而是：每次口径不同、清洗步骤没记录、图表缺标签、交接给同事时无法复现。团队希望 Agent 接手，但要求每一步可追溯，且默认行为明确。

需求

类型要求可验证标准
正确金额、日期、缺失值处理有明确口径报告列出每一步清洗与影响行数
可复现同一输入两次运行结果一致（除时间戳）输出文件哈希一致；脚本固定版本
透明不静默删行、不自动填 0、不猜币种报告中出现“清洗记录”与“局限”
可读每张图有标题、轴标签、单位图表断言检查标签存在
可维护口径与 schema 独立于流程新增列含义只需改 reference

设计与权衡

被否决的方案

  1. 给一段“用 pandas 分析 CSV”的通用教程。 模型本来就会；没有项目 schema、编码与口径，等于没写。否决理由：缺少真实专长。
  2. 只交付一个 Jupyter notebook。 适合探索，不适合 Agent 每周执行；隐藏状态导致结果依赖执行顺序。否决理由：不可复现。
  3. 自动填补缺失值与异常值。 看起来“干净”，实际改变了业务事实；不同周的口径不一致。否决理由：不可追溯。
  4. 让 Agent 每次根据数据自行决定清洗策略。 结果随模型状态波动。否决理由：不可评估。
  5. 把所有 schema 与规则塞进 SKILL.md。 正文超预算，且大部分规则每周只用一次。否决理由：上下文成本。

采用的结构

  • 先概要，后分析：先跑 profile，确认行数、列名、缺失与类型；异常时停止。
  • 默认清洗规则：明确“删什么、不删什么、什么时候停”，而不是让模型自由发挥。
  • 脚本承担重复计算：profile、check_output；图表可由脚本或明确指令生成。
  • schema 进 references：列含义、指标口径、表关系；按条件加载。
  • 报告模板：概览、清洗记录、关键发现、图表、局限，缺一不可。

这与来源的两个模式对应：提供默认值而非菜单；把只在特定情况下需要的细节放入按需加载的资源。[源站]（best-practices.md）

取舍

决定代价为什么接受
缺失值不自动填图表可能出现空缺保留事实；填 0 会扭曲均值与趋势
币种不明就停止可能中断自动流程混币种求和是严重错误，且难以事后发现
固定默认库不适用于所有环境减少选择成本；环境要求写入 compatibility
清洗只做保守操作脏数据仍需人工处理自动“修好”会掩盖数据质量问题
图表取 Top N长尾类别不可见可读性优先；完整数据仍在输出 CSV
schema 按需加载多一次读取主文件保持精简；只在需要解释列时读

三项关键取舍：决定、被否决的替代方案与理由

决定被否决的替代方案为什么
先 profile 再分析直接读入后开始统计编码、列数、缺失会在源头污染结果；profile 能在分析前拦截
缺失值保留并报告自动填 0 或均值填 0 会扭曲均值与趋势；保留事实并说明，才能复核
币种/日期口径不明就停止按最常见格式自行解析混币种求和、日月颠倒的错误难以事后发现

第一个取舍把一次额外脚本运行换成可解释性。profile 不产生业务结论，却能提前发现编码错误、列数不齐和缺失分布；没有这一步，后续图表可能建立在一份被误读的数据上。代价是流程多一步，收益是错误早暴露。

第二个取舍拒绝“看起来干净”的自动填补。缺失值填 0 会让均值、同比和图表全部偏移，而且偏移不会以错误形式出现；保留缺失并在报告中列明，读者才能判断结论是否可靠。真正需要填补时，应由用户明确指定方法。

第三个取舍把不确定性交回给人。币种混用、日期顺序不明时，任何自动解析都可能在部分行上正确、部分行上错误；这种“一半对”的结果最难发现。停止并询问口径，虽然降低自动化率，却避免了不可追溯的汇总错误。

完整 SKILL.md

---
name: csv-analyzer
description: Analyze CSV and tabular data files — profile columns, clean missing values, compute summary statistics, add derived columns, and generate labeled charts. Use when the user has a CSV, TSV, or Excel export and wants to explore, transform, or visualize it, even if they don't mention "CSV" or "analysis".
compatibility: Requires Python 3.10+ with pandas and matplotlib.

## 何时使用 / 不适用

当用户提供 CSV、TSV 或 Excel 导出，想要探索、清洗、统计或可视化数据时使用。不适用于修改工作簿公式与格式、执行数据库 ETL，或在币种/时区口径不明时强行汇总。

# CSV Analyzer

## 流程

1. **先做概要**：运行 `python scripts/profile.py <file>`，记录行数、列数、缺失值与疑似类型。
   - 行数为 0 或列名为空时停止，报告文件问题。
2. **确认口径**：金额、日期、百分比的处理方式不明确时先询问；不要自行假设币种或时区。
3. **清洗**：按下方默认规则处理，并在报告中列出每一步改动。
4. **分析**：计算用户要求的指标；未指定时给出数量、缺失、数值分布与前三类分组。
5. **图表**：每张图必须有标题、坐标轴标签与单位；类别过多时取 Top N 并注明。
6. **自检**：运行 `python scripts/check_output.py output/`，确认图表文件与报告字段齐全。

## 清洗默认

- 完全重复行：删除，并报告删除数量。
- 数值列缺失：保留缺失，不自动填 0；在报告中列明。
- 文本列：去除首尾空格；不自动统一大小写。
- 日期：先尝试 ISO 8601；其他格式列出样例后再解析。
- 货币：识别 `$`、`¥`、`€` 与千分位逗号；无法判断币种时停止并询问。
- 异常值：不自动删除；在报告中标记并给出判断依据。

## 输出模板

```markdown
## 数据概览
- 文件：<path>；行数：<n>；列数：<m>
- 时间范围：<start> 至 <end>（若适用）

## 清洗记录
- <操作>：影响 <n> 行

## 关键发现
- <发现>（附数值与口径）

## 图表
- <chart.png>：<说明>

## 局限
- <缺失、口径不明或样本过小的部分>
```

## Gotchas

- 中文 CSV 常见 GBK/GB18030 编码；UTF-8 读取失败时按 `utf-8-sig → gb18030` 重试，并在报告中注明。
- Excel 导出的“日期”可能是序列号（如 45292）；先确认再转换，不要直接当字符串。
- 金额列可能混有 `1,200`、`$1200`、`1200元`；统一清洗后再求和，否则会得到字符串拼接。
- 分组均值在分母为 0 时会产生 inf/NaN；输出前替换为“无数据”并说明。
- 图表不要使用默认英文标题；标题与轴标签必须与用户语言一致。

## 参考文件

- 当需要理解列含义、指标口径或表之间的关系时，读 `references/schema.md`；不要根据列名猜测业务含义。
- 当用户要求特定图表样式时，读 `assets/chart-style.md`，按其配色与标注规则生成。

验证方法

  1. 三套数据集。 干净 UTF-8 数据、GBK 中文数据、含货币符号与混合日期的脏数据；每套配一份人工核对过的期望结果（行数、缺失数、总额、图表数量）。
  2. 断言。 输出报告包含五个小节；图表文件存在且标题/轴标签非空；金额总额与期望一致（允许小数位差异）；清洗记录中的行数变化可加总回原行数。
  3. 可复现性。 同一输入运行两次，除时间戳外的输出一致；脚本版本固定。
  4. 失败路径。 空文件、列数不齐、币种混合应分别触发停止或明确询问，而不是静默继续。
  5. 对照。 同一任务跑“无技能”版本，比较：是否报告清洗步骤、图表是否有标签、缺失值是否被擅自填充。技能的价值应体现在这些具体差异上。
  6. 人工复核。 让运营同事看报告，确认口径与业务理解一致；这是断言覆盖不到的部分。
CHECKPOINT

合格标准示例：三套数据全部产出五节报告；金额误差为 0；两次运行输出一致；空文件与混币种均被拦截；运营同事能根据“清洗记录”复述每一步改动。

常见失败模式

失败表现根因预防
编码静默丢失中文列名变乱码，后续按错误列名处理只用 UTF-8 读取，未检查替换字符按 utf-8-sig → gb18030 重试并报告
货币解析错误金额求和处理成字符串拼接未清洗符号与千分位统一清洗；无法判断币种时停止
日期歧义01/03 被解析为 1 月 3 日或 3 月 1 日未确认日/月顺序列出样例并询问；优先 ISO 8601
除零与 inf分组均值出现 inf/NaN，图表断裂未处理空分母输出前替换为“无数据”并说明
图表无标签只有图形，无法解读模板未强制断言检查标题、轴标签、单位
静默删行报告行数比原文件少，但未说明清洗步骤未记录清洗记录必须列出影响行数
描述过宽用户要改 Excel 公式也触发description 只写“处理数据”明确“分析本地表格并生成图表”的边界
不可复现两次结果不同依赖随机采样或隐藏 notebook 状态固定随机种子；脚本化；记录版本

可迁移的经验

  • 数据分析技能的核心不是算法，而是口径、默认值与可追溯性。
  • 把“不自动做什么”写清楚，往往比多写十个分析函数更有价值。
  • 先 profile 再分析，能在源头拦截大部分脏数据问题。
  • 报告模板与断言让“看起来完成了”变成“可以复核”。

数据分析技能的验证要覆盖“口径”而不只是“数字”。同一份 CSV，按不同缺失值处理、不同币种假设、不同日期顺序，可以得到都“看起来合理”的结果。因此断言里要包含清洗记录、缺失计数和口径说明，而不只是最终图表。能让读者复述每一步改动，才算可追溯。

可复现性也是验证的一部分。同一输入运行两次，除时间戳外的输出应一致；随机采样要固定种子；脚本版本要记录。若两次结果不同，先查隐藏状态与随机性，再查数据。一个不能复现的分析，无法用于业务决策，也无法在出问题时定位原因。

练习

基础

为“金额列”写三条清洗规则：一条处理货币符号、一条处理千分位、一条处理币种不明的情况。

提示与自检

示例：去掉 $ ¥ € 等符号并记录币种；去掉千分位逗号并转为数值；若同一列出现多种币种符号，停止并要求用户指定换算口径。第三条是关键：不要默认按 1:1 相加。

基础

回到本页第一个概念小节，用两三句话说明它解决什么问题，并举一个你工作中会遇到的例子。

提示与自检

合格答案要包含“问题—做法—具体场景”三部分；只复述小节标题，或举一个与本页无关的例子，都不算完成。

进阶

设计一条断言，验证“清洗记录中的行数变化可加总回原行数”。写出断言文本与所需的中间数据。

提示与自检

断言：“原行数 − 删除行数 = 输出行数”，需要 profile 输出的原始行数、清洗记录中的删除计数、最终输出行数。若清洗包含合并或拆分，需要额外的换算说明，否则断言不成立。

进阶

把本页的方法用到你自己的一个真实任务上，写出两条可执行指令和一个别人能照着做的验证方式。

提示与自检

两条指令要具体到字段、命令、阈值或判断标准；验证方式必须给出可观察的结果，例如某个文件存在、某条命令退出码为 0、某个字段等于期望值。

挑战

把技能扩展到 Excel（.xlsx）输入。需要新增哪些文件、改哪些触发？如何避免把“读取 xlsx”与“编辑 xlsx 公式”混为一谈？

可打印检查清单

从设计前到发布前的逐项检查，可直接打印在 A4 纸上，也可作为评审他人 Skill 的对照表。

阶段：参考 · 建议 8 分钟 · 先修：读完 S3

从选题到发布前的逐项检查。可直接打印在 A4 纸上，也可以作为评审他人技能的对照表。勾选状态只保留在当前页面，不会保存。

一、设计前

  • 这个任务最近三个月至少出现过三次。一次性任务往往没有可复用的稳定模式。
  • 我能说出至少三个“外行会做错、内行会做对”的决定。这是技能价值的来源。
  • 我知道正确结果长什么样，并能用命令或观察来验证。没有验证方式就无法评估。
  • 我能用一句话说清技能范围，且与相邻能力区分开。范围决定触发与正文。
  • 我确认这不是模型本来就能稳定完成的任务。否则技能只是增加成本。

二、Frontmatter 与描述

  • 目录名与 name 完全一致。规范硬性要求。
  • name 只含小写字母、数字与连字符，不以连字符开头/结尾，无连续连字符，≤64 字符。
  • description 非空，1–1024 字符。规范硬性要求。
  • 描述同时说明“做什么”和“什么时候用”。
  • 描述覆盖至少 3 种用户可能说法，包括不点名领域的场景。
  • 描述能用一句话划出与相邻技能的边界。
  • YAML 无 Tab、无未加引号的多余冒号；长描述用块标量或引号。
  • 仅在确有环境要求时写 compatibility，且 ≤500 字符。
  • metadata 的值均为字符串（版本号加引号）。
  • allowed-tools（如使用）没有被当作权限控制。

三、正文内容

  • 没有解释模型已知的通用概念。“补缺的，省已知的”。
  • 随机抽三段，每段都能回答“没有它 Agent 会不会做错”。
  • 至少一条 Gotcha 描述具体错误、原因与正确做法，含实际字段/命令/阈值。
  • 流程步骤有明确顺序，隐含依赖已写明。
  • 高风险步骤有停止条件，而不是“小心操作”。
  • 输出格式用模板或真实样例约束，而不是“结构清晰”。
  • 多方案处给出默认值与明确逃生口，而不是菜单。
  • 脆弱步骤给了精确命令或固定顺序。
  • 开放步骤给了判断标准与原因，而不是机械步骤。
  • 方法能泛化到同类任务，而不是只对某个实例有效。

四、结构

  • SKILL.md 少于 500 行（建议 50–150 行）。规范建议，不是硬校验。
  • 每次执行都要用的内容在主文件；低频细节在支持文件。
  • 每个支持文件都有加载触发，写成“当 X 时读 Y，用于 Z”。
  • 触发条件是可观察的：退出码、扩展名、缺失字段、流程阶段。
  • 所有引用从主文件出发，保持一层深度。
  • 文件命名表达内容，大小写在全平台一致。
  • 主文件中的参考清单列出了每个支持文件的用途。
  • 拆出去的内容没有与主流程强耦合到无法执行。

五、脚本（如使用）

  • 脚本不等待交互输入，所有输入来自参数、环境变量或 stdin。
  • --help 给出用途、选项、示例与退出码。
  • 错误信息说明错在哪、期望什么、下一步怎么做。
  • 结构化数据走 stdout，诊断走 stderr。
  • 失败返回非零退出码，且不同失败类型有不同码。
  • 重复运行安全（幂等），破坏性操作支持 --dry-run 或显式确认。
  • 输出体积有上限或分页机制。
  • 依赖与运行时版本写进 compatibility 或正文前置检查。

六、触发评估

  • 至少 6 条触发查询（建议 20），正负大致各半。
  • 至少 2 条近邻负例：共享关键词但任务不同。
  • 正例覆盖正式、随意、口语、未点名领域等说法。
  • 每条查询运行 3 次，记录触发率，而不是只跑一次。
  • 训练集与验证集固定划分，验证集不参与修改。
  • 修改依据是失败类型（太窄/太宽），不是堆关键词。
  • 最终描述 ≤1024 字符，并用未参与优化的新查询做一次检验。
  • 能出示完整记录表：查询、应否触发、触发次数、判定。

七、输出评估

  • 至少 3 个评估用例，含提示、预期输出与可选输入文件。
  • 至少一个用例覆盖边界或歧义输入。
  • 每个用例至少 2 条断言，可由输出直接检查。
  • 断言不过度依赖精确措辞；PASS 必须附证据。
  • 有“有技能 / 无技能”或“新旧版本”的对照。
  • 记录通过率、token 与耗时，并解释收益是否值得成本。
  • 检查“两边都通过”的断言，删除或替换无信息量的检查。
  • 至少有一次人工评审，反馈具体到可修改之处。

八、发布

  • skills-ref validate 或本地校验脚本通过。
  • 在至少一个真实客户端中可见、可激活、可执行。
  • 许可证与来源信息完整；未包含内部敏感信息。
  • 目录自包含，无绝对路径、无对外部主机的运行时依赖。
  • 设计说明写清了范围、三个取舍、触发策略与验证结论。
  • 反模式清单逐项排除。

九、毕业门禁

  • 第 1–8 节全部检查完毕，没有“暂时跳过”。
  • 自评 ≥80/100，且真实专长、触发描述、验证闭环均 ≥3 分。
  • 能向他人解释三个取舍：范围、references、脚本。
  • 他人能按说明复现你的验证。

打印提示：浏览器打印时选择 A4、默认边距；导航、搜索与按钮会自动隐藏，复选框以方框打印，便于手写勾选。

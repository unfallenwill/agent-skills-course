学习路径：五个阶段与毕业自检

五个阶段从认知准备走到交付与迁移。每一阶段都写清进入状态、离开状态、先修要求、预计时间、组成页面与可观察能力，最后给出毕业自检门禁。

阶段：全课程 · 建议 15 分钟

路径不是把页面排个序，而是保证每一阶段结束时你都获得一种可观察的能力。下面每个阶段都写明：你带着什么进来、带着什么离开、需要先会什么、要花多久、由哪些页面组成，以及离开时应该能演示什么。

总时间与建议节奏

完整路径约 18 小时（含教程、案例与毕业项目，不含额外练习）。建议每周投入 3–4 小时，五周完成；也可以用一个周末完成“速通路线”。时间估计属于[本课程观点]，会因你的编程背景和客户端差异而浮动。

为什么这样排序

很多教程从“复制这段 frontmatter”开始，学习者能做出一个能跑的例子，却不知道它为什么能跑。一旦任务变复杂，就会退回“把所有东西塞进提示词”的旧习惯。本课程刻意把机制放在格式之前：先理解 Agent 如何加载上下文，再理解为什么规范要这样设计，最后才动手。

三个排序原则：

  1. 先机制后格式。 不知道渐进披露（progressive disclosure）解决什么问题，就会把 SKILL.md 写成一篇长文。
  2. 先内容后触发。 描述写得再漂亮，也救不了一个内容空洞的 Skill；但内容很好、触发失败的 Skill 很常见，所以触发训练紧随设计之后。
  3. 先单点后系统。 教程每次只增加一种新结构（references、scripts、评估），案例再把这些结构组合起来。

S1 认知准备：建立正确的心智模型

S1 · 约 2 小时

学习者状态

进入：用过聊天式 AI，能写清楚需求；但不清楚 Agent 如何“动手”，没听过 token 预算、上下文窗口、渐进披露。可能会把 Skill 理解成“更长的提示词”。

离开：能用自己的话解释 Agent 循环、工具调用闭环、上下文为什么是稀缺资源，以及渐进披露解决了什么矛盾。能判断一个任务是否值得写成 Skill。

先修要求：无。需要会创建文件夹、编辑文本文件；后续教程需要终端。

组成页面：

  • 什么是 Agent：从模型到会动手的系统
  • 工具调用：Agent 如何真正执行动作
  • 上下文窗口与 Token：为什么上下文是稀缺资源
  • 提示词、指令与文件式配置
  • 渐进披露：为什么不能把所有内容一次塞进去

可观察能力：不看笔记，画出“发现 → 激活 → 执行”三阶段，并指出每一阶段 Agent 实际读取了什么；举出一个“适合写成 Skill”和一个“不值得写成 Skill”的任务，并说明理由。

S2 读懂规范：从会用到能判断对错

S2 · 约 2.5 小时

学习者状态

进入：知道 Skill 是按需加载的能力包，但没逐条读过格式规范，看到别人的 SKILL.md 只能凭感觉判断好坏。

离开：能独立写出 frontmatter 合法的 SKILL.md；能当场指出非法的 name；能解释三级加载各自的 token 预算；能运行 skills-ref validate 并读懂输出；知道项目级与用户级技能的发现路径和覆盖规则。

先修要求：S1。能读懂 YAML 键值对与 Markdown 标题即可。

组成页面：

  • Skill 的解剖：目录结构与 SKILL.md
  • Frontmatter 字段完全指南
  • 渐进披露的工程实现：预算、拆分与加载触发
  • 生命周期：发现、激活、执行
  • 校验、兼容性与常见坑

可观察能力：拿到任意一个 Skill 目录，能在五分钟内列出结构问题（name 不匹配、描述缺失触发条件、正文超长、引用层级过深），并给出修改方案。

S3 写出好内容：从合格到有效

S3 · 约 5 小时

学习者状态

进入：能写出格式正确的 Skill，但内容容易变成通用教程：解释模型已经知道的概念，堆砌“注意质量”“处理边界情况”这类空话，或者把 300 行细节全塞进主文件。

离开：能从一次真实任务中提炼专长；能对每一段内容问“没有它 Agent 会做错吗”；能按任务的脆弱程度决定给自由还是给死命令；能熟练使用 Gotchas、模板、清单、验证循环、计划-校验-执行、脚本六种模式。完成教程 1–3 后，你手上有三个可运行、结构不同、难度递增的 Skill。

先修要求：S2。教程 1 需要 VS Code 与 GitHub Copilot（或其他支持 Skills 的客户端）；教程 3 需要 Node.js 18+。

组成页面：

  • 从真实专长出发，而不是让模型凭空编
  • 用真实执行打磨 Skill
  • 上下文经济：加该加的，删该删的
  • 结构设计：渐进披露与文件组织
  • 控制校准：自由度与规定性的取舍
  • 高效指令模式：坑点、模板、清单、验证循环
  • 教程 1：20 分钟做出第一个 Skill
  • 教程 2：用 references/ 给 Skill 减负
  • 教程 3：打包 scripts/ 并建立验证循环

可观察能力：独立写出一个 80–150 行的 SKILL.md，包含至少一个具体的坑点、一个默认方案、一个可验证的完成标准；能说明哪些内容被刻意删掉以及为什么。

S4 触发与评估：从“我觉得行”到“有证据”

S4 · 约 2.75 小时

学习者状态

进入：能写出内容不错的 Skill，但不知道它在真实提问下会不会被调用，也无法回答“它到底比不用好多少”。

离开：能写出命令式、面向用户意图、覆盖边界的 description；能构造约 20 条真实查询（含近邻负例），按 3 次运行计算触发率；能划分训练/验证集并解释为什么不能拿验证集调参；能写评估用例、断言、评分记录和基准对比，并用 token 与时间成本解释收益。

先修要求：S3。教程 4 需要一个能观察工具调用的客户端；无法自动化时可按教程中的手工流程记录。

组成页面：

  • 描述字段：Skill 触发的唯一入口
  • 触发评估：用查询集调准 description
  • 输出质量评估：断言、基线与迭代
  • 教程 4：写 3 个评估用例并调好 description

可观察能力：拿出一张表：查询、是否应触发、3 次中触发次数、触发率、判定；再拿出一张对照表：有/无 Skill 的通过率、平均 token、平均耗时。能指出至少一条被删掉的断言及原因。

S5 交付与迁移：从会做一个到会评审一类

S5 · 约 6.25 小时

学习者状态

进入：能完成单个 Skill 的设计与评估，但缺少跨领域经验，不确定哪些做法可迁移，也缺少评审他人的标准。

离开：读完文档处理、代码评审、数据分析三个案例，能识别每个案例中被否决的方案及理由；完成毕业项目并通过 80 分门槛；能使用评分表与反模式清单评审他人的 Skill，指出具体问题而非泛泛评价。

先修要求：S4。毕业项目需要你自选一个真实、重复出现的任务。

组成页面：

  • 案例 1：PDF 表单批量填写（文档处理）
  • 案例 2：团队代码评审（代码工作流）
  • 案例 3：运营 CSV 分析（数据分析）
  • 毕业项目：设计并发布你自己的高质量 Skill
  • 可打印检查清单

可观察能力：交付一个完整目录（SKILL.md、至少一个支持文件、评估用例），附一份 400 字以内的设计说明，说明范围、取舍、触发策略与验证结果；自评分数与导师评分差距不超过 10 分。

毕业自检门禁：你已经可以独立设计 Skill 了

下面 12 条不是“读过即可”，而是能在 20 分钟内演示或出示证据的检查项。至少通过 10 条，且第 1、2、3、9 条必须通过，才算跨过门禁。[本课程观点]

  1. 能被发现：在你的项目里创建 .agents/skills/<name>/SKILL.md，客户端的技能列表（例如 Copilot Chat 的 /skills）能看到它。
  2. 命名合法：name 与父目录完全一致，匹配 ^[a-z0-9]+(-[a-z0-9]+)*$，长度不超过 64 个字符。
  3. 描述可用：description 在 1–1024 字符之间，同时说明“做什么”和“什么时候用”，并包含至少 3 个真实触发说法。
  4. 体量受控：SKILL.md 正文少于 500 行；若接近上限，至少有一个 references/ 文件，并写清“满足什么条件时读它”。
  5. 没有废话：随机抽三段正文，每段都能回答“没有这句，Agent 会不会做错”。不能回答的已删除。
  6. 坑点具体：至少有一个 Gotcha 描述“不写就会犯的具体错误”，包含实际字段名、命令或边界值，而不是“注意质量”。
  7. 控制有度：脆弱步骤给出精确命令或固定顺序；开放步骤给出判断标准与原因，而不是死板步骤。
  8. 脚本友好：如包含脚本，它不等待交互输入，有 --help，失败时输出可操作的错误信息并返回非零退出码。
  9. 触发有数据：有至少 6 条触发查询（其中至少 2 条近邻负例），每条运行 3 次并记录触发率；训练集与验证集分开。
  10. 质量有对照：有至少 3 个输出评估用例、可验证的断言，以及“有 Skill / 无 Skill”的通过率对照；能说出 token 与时间代价。
  11. 取舍能解释：能向他人说明三个决定：范围为什么这样切、哪些内容放进 references、为什么用或不用脚本。
  12. 自评达标：用毕业项目评分表自评不低于 80/100，且反模式清单逐项排除。

门禁结论

如果第 1、2、3、9 条通过，其余至少再通过 6 条：你已经具备独立设计、验证和维护 Skill 的能力，可以开始为团队沉淀技能库。

如果任何一条必需项未通过，回到对应阶段：第 1–2 条回 S2，第 3、9 条回 S4，第 4–7 条回 S3，第 8 条回教程 3，第 10–11 条回 S4 与 S5，第 12 条回毕业项目。

三条可选路线

速通：约 6 小时

适合先建立整体印象，之后再补细节。

  • 读 b1、b3、b5
  • 读 c1、c2
  • 做 教程 1
  • 读 e1 与 案例 1

标准：约 18 小时

按 S1 到 S5 顺序完成，做每页的基础与进阶练习，完成毕业项目。

  • 覆盖全部 26 个教学页面
  • 完成教程 1–4
  • 毕业项目自评 ≥80

深入：25 小时以上

面向要在团队内推广 Skill 的人。

  • 做完所有挑战练习
  • 触发评估每条查询跑 5 次，做两轮完整迭代
  • 评审一位同伴的 Skill，并写一份改进建议
  • 读来源页中的客户端实现指南，理解加载机制

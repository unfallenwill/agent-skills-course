教程 1：20 分钟做出第一个 Skill（roll-dice）

从空目录开始，写出一个能真正掷骰子的 Skill：创建目录、写 frontmatter、在 Agent 模式下确认被发现、观察激活与执行。

阶段：S3 写出好内容 · 建议 25 分钟 · 先修：S2 完成；本机有 VS Code 与 Copilot

这是最短的一次端到端：一个目录、一份十几行的 SKILL.md，然后亲眼看到 Agent 发现它、加载它、按它执行。做完你会对“发现—激活—执行”有具体感受，而不只是概念。

前置条件

  • 安装 VS Code，并安装 GitHub Copilot 扩展。
  • 能在 VS Code 中打开一个项目文件夹，并使用 Copilot Chat 的 Agent 模式。
  • 会打开终端。Windows 可用 PowerShell 或 Git Bash；macOS / Linux 用系统终端。

[源站] 本教程的步骤与文件内容来自来源快速入门；它使用 VS Code，但 Agent Skills 是开放格式，同一个技能也能在 Claude Code、OpenAI Codex 等兼容客户端中工作。（quickstart.md）

目录位置因客户端而异

VS Code 默认扫描项目根目录下的 .agents/skills/。其他客户端可能扫描自己的目录或用户主目录；如果你的客户端不是 VS Code，先查它的文档，再替换下面的路径。技能的内容格式不变。

步骤 1：创建目录

在项目根目录执行（Git Bash / macOS / Linux）：

mkdir -p .agents/skills/roll-dice

PowerShell：

New-Item -ItemType Directory -Force -Path .agents/skills/roll-dice

最终结构必须是：

你的项目/
└── .agents/
    └── skills/
        └── roll-dice/
            └── SKILL.md

注意 SKILL.md 在 roll-dice/ 里面，而不是直接在 skills/ 下。父目录名 roll-dice 必须与 frontmatter 里的 name 完全一致。

步骤 2：写入 SKILL.md

创建 .agents/skills/roll-dice/SKILL.md，内容如下（可直接复制）：

---
name: roll-dice
description: Roll dice using a random number generator. Use when asked to roll a die (d6, d20, etc.), roll dice, or generate a random dice roll.
---

## 何时使用 / 不适用

当用户要求掷骰、生成桌面游戏随机数（d6、d20、3d6 等）时使用。不适用于密码、验证码、抽奖等需要安全随机性或可审计公平性的场景；遇到这类请求应说明限制，不要用本技能的命令冒充安全随机源。

## 参考文件

当用户使用 3d6、4d6kh3 等骰子记号，或需要解释结果时，读 `references/dice-notation.md`，按其中的记号规则解析并逐项报告。

To roll a die, use the following command that generates a random number from 1
to the given number of sides:

```bash
echo $((RANDOM % <sides> + 1))
```

```powershell
Get-Random -Minimum 1 -Maximum (<sides> + 1)
```

Replace `<sides>` with the number of sides on the die (e.g., 6 for a standard
die, 20 for a d20).

逐部分解释：

  • name：技能标识，必须与文件夹名 roll-dice 一致。
  • description：告诉 Agent 什么时候用。它包含 “roll a die”、“d6, d20”、“roll dice”、“random dice roll”，覆盖了用户可能说的几种方式。
  • 正文：Agent 激活后要遵循的指令。这里只写了一件模型不知道的事：用哪条终端命令，以及如何替换面数。

整份文件不到 20 行。它没有解释骰子是什么，也没有介绍随机数原理——那些模型都知道。

步骤 3：确认技能被发现

  1. 在 VS Code 中打开项目文件夹。
  2. 打开 Copilot Chat 面板。
  3. 在面板底部把模式切换为 Agent。
  4. 输入 /skills，确认 roll-dice 出现在列表中。

如果没出现，先检查文件是否精确位于 .agents/skills/roll-dice/SKILL.md（相对于项目根目录），并确认文件名大小写完全一致。[源站]

步骤 4：触发并观察执行

在同一个聊天里输入：

Roll a d20

Agent 应当激活 roll-dice 技能。它可能会请求运行终端命令的权限，允许它。然后它会运行命令，返回一个 1 到 20 之间的随机整数。

预期结果：你看到一个具体的数字，例如 14；展开工具调用记录，可以看到它读取了 SKILL.md 并执行了一条类似 echo $((RANDOM % 20 + 1)) 的命令。具体工具调用形态因客户端而异，但“读文件 → 跑命令 → 返回数字”的顺序应当可观察。

预期结果

这一课的预期结果不是“Agent 回答了一个数字”，而是你能观察到完整链路：技能出现在列表中、被加载、执行了终端命令、返回了范围内的结果。只看到自然语言答案，无法证明技能真的生效。

检查点

逐条对照上面的检查点；任何一条失败，都先按“如果出错了”排查，再继续下一课。尤其是第 4、5 条，它们验证的是执行，而不是回答。

CHECKPOINT

逐条执行并确认：

  1. ls .agents/skills/roll-dice/SKILL.md 能列出文件。
  2. grep -n "^name: roll-dice$" .agents/skills/roll-dice/SKILL.md 输出行号，说明 name 精确匹配。
  3. 在 Copilot Chat 的 /skills 列表中能看到 roll-dice。
  4. 输入 “Roll a d20” 后，Agent 实际执行了终端命令，而不是凭语言能力编一个数字；返回值为 1–20 的整数。
  5. 再输入 “Roll a d6”，返回值为 1–6 的整数，说明它把面数替换进了命令。

第 4、5 条是关键：如果它只是回答“你掷出了 12”却没有工具调用，说明技能可能没被加载，或模型选择自行作答。

它为什么能工作

[源站] 会话启动时，Agent 扫描默认技能目录，只读 name 与 description，知道有个技能可能与掷骰相关；当你说 “Roll a d20”，问题与描述匹配，它加载完整正文；随后按正文执行命令，并把 <sides> 替换为 20。整个过程就是渐进披露：启动时只付出一行元数据的成本，激活时才读全文。（quickstart.md）

常见错误

现象原因修复
/skills 里没有文件放错层级，例如 .agents/skills/SKILL.md确保在 .agents/skills/roll-dice/SKILL.md
有警告或校验失败name 与目录不一致，或含大写/下划线同时改目录名与 name
技能在列表里，但不触发描述没有覆盖你的说法；或模型认为任务太简单，不需要技能换一种说法测试；或在描述中加入该说法
Agent 直接回答数字，不运行命令不同模型的工具使用可靠性不同换一个模型重试；来源明确提示这是已知差异
PowerShell 命令报语法错误在 PowerShell 里用了 bash 的 $((...))使用 SKILL.md 中的 PowerShell 版本，或改用 Git Bash
数字总是同一个没有真正执行随机命令，或用了固定值展开工具调用查看实际命令

你刚刚验证了什么

  • Skill 的最小单位是“目录 + SKILL.md”，不需要构建、打包或注册。
  • 描述决定触发；正文决定执行；两者缺一不可。
  • 一个有用的技能可以非常短。短不等于简陋，前提是只写模型不知道的内容。

如果出错了

下面按“症状—原因—修复”列出最常见的三类问题。先定位症状，再检查原因，不要同时改多个地方；每次只改一处，重跑同一检查点。

症状可能原因修复
/skills 列表里没有 roll-dice文件不在 .agents/skills/roll-dice/SKILL.md，或文件名大小写不一致确认目录层级与 SKILL.md 拼写，重新打开会话
技能在列表里，但不触发描述没有覆盖你的说法，或模型认为任务太简单换一种说法；检查描述是否包含 roll dice、d20 等场景
Agent 直接报数字，没有工具调用模型选择自行作答，未执行命令展开工具记录；换一个模型重试；要求给出命令输出

把这次练习当成一次完整的验收：你不是在检查“答案像不像”，而是在检查“链路是否打通”。发现、激活、执行、验证四步都能被观察到，才说明这个技能真正可用。以后写更复杂的技能时，也先用最小版本打通这四步，再补内容；否则一旦失败，你很难判断问题出在格式、描述还是客户端。

练习

基础

把技能改成支持 d100，并验证一次。需要改哪几处？

提示与自检

正文不需要改（它已经用 <sides> 参数化）；描述可加入 “d100” 以覆盖说法。验证 “Roll a d100” 返回值在 1–100。若你硬编码了 20，说明没理解参数替换。

基础

回到本页第一个概念小节，用两三句话说明它解决什么问题，并举一个你工作中会遇到的例子。

提示与自检

合格答案要包含“问题—做法—具体场景”三部分；只复述小节标题，或举一个与本页无关的例子，都不算完成。

进阶

让技能支持“掷 3 个 d6 并求和”。写出正文修改，并说明如何验证每个骰子都在 1–6、总和正确。

提示与自检

可用循环执行三次并累加，或生成三个随机数后求和；输出应同时给出每个结果与总和。验证：连续运行多次，检查每个值范围与总和等于三者之和。若只返回总和，无法验证单骰范围。

进阶

把本页的方法用到你自己的一个真实任务上，写出两条可执行指令和一个别人能照着做的验证方式。

提示与自检

两条指令要具体到字段、命令、阈值或判断标准；验证方式必须给出可观察的结果，例如某个文件存在、某条命令退出码为 0、某个字段等于期望值。

挑战

把描述改写成能覆盖中文口语（“帮我扔个骰子”“跑团要个 d20”“随机来个 1 到 20 的数”），同时避免在用户说“生成随机密码”时误触发。测试至少 6 条说法并记录结果。

评分点
  • 完整回应题目中的两个关键要求：2 分
  • 给出可验证的检查、示例或对照：2 分
  • 说明一个取舍、边界或失败情况：1 分

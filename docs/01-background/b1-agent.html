S1 认知准备

什么是 Agent：从模型到会动手的系统

先建立最基本的心智模型：大语言模型、Agent、Agent 循环，以及 Agent 为什么需要外部知识与流程。

阶段：S1 认知准备 · 建议 25 分钟

[本课程观点] 在谈论 Skill 之前，得先知道它服务于谁。这一页建立三个概念：大语言模型、Agent，以及 Agent 为什么经常“看起来很聪明，却做不对你的活”。

大语言模型：会预测下一个词，但不会自己动手

[本课程观点] 大语言模型（Large Language Model，LLM）是一类经过海量文本训练的模型，核心行为是根据已有上下文预测下一个 token（词元，模型处理文本的基本单位）。它擅长理解自然语言、总结、改写、生成代码和推理，但有一个根本限制：它只输出文本，不直接操作你的文件、数据库或浏览器。

[本课程观点] 本课程采用一个够用的简化定义：LLM 是一个“根据上下文生成下一步内容”的函数。它没有记忆，不会在两轮对话之间自动保留状态；所谓“记得”，是因为客户端把之前的对话又放回了上下文。这个简化会影响你后面理解 Skill 的加载方式。

[本课程观点] 理解“预测下一个 token”这件事，能帮你判断模型的边界。它可以把一段需求改写成结构化指令，也能解释报错，但它不会因为读过你的代码就真的知道你们项目的约定。它生成的内容是否可信，取决于上下文里是否包含足够的事实，以及你是否给了可验证的检查。把模型当成一位知识面很广、但没有你们公司记忆的顾问，比把它当成会自动执行任务的同事更准确。这个区别会贯穿整门课：Skill 做的，就是把顾问缺少的那部分事实与流程补上。

Agent：让模型进入“观察—决策—行动”的循环

Agent（智能体）不是一个特定的模型，而是一种系统结构：模型在循环中读取环境信息、决定下一步动作、调用工具执行、观察结果，再决定是否继续。Anthropic 在工程文章中的区分很有用：工作流（workflow）沿预定义的代码路径执行，而 Agent 由 LLM“动态地指导自己的流程和工具使用”。[外部: https://www.anthropic.com/research/building-effective-agents] 参见 Building effective agents（检索于 2026-11-25）。

[外部: https://www.anthropic.com/research/building-effective-agents] 一个典型循环是：

  1. 观察（observe）：读取用户消息、当前文件、命令输出、网页内容。
  2. 决策（decide）：判断目标是否完成；如果没完成，决定调用哪个工具、传什么参数。
  3. 行动（act）：发出工具调用请求（tool call），由客户端或运行环境真正执行。
  4. 再观察：拿到执行结果，回到第 1 步。直到完成、失败或达到停止条件。

[本课程观点] 这个四步循环是本课程用来解释 Agent 行为的模型，不是规范的一部分。不同产品的实现细节不同，但“模型决定、环境执行、结果回灌”这个结构是共通的。

[外部: https://www.anthropic.com/research/building-effective-agents] 判断一个系统是不是 Agent，可以看两点：下一步做什么是否由模型根据当前观察决定，以及模型是否能通过工具改变环境。只按固定顺序调用几次模型的工作流，即使用了 LLM，也不是 Agent。反过来，一个 Agent 必须有停止条件，否则会在“再试一次”的循环里耗尽预算。常见的停止条件包括任务完成、验证通过、连续失败达到上限、需要人工授权。设计 Skill 时，这些停止条件应该写进正文，而不是留给模型临场发挥。

一个具体例子：整理下载文件夹

[本课程观点] 假设你让 Agent：“把下载文件夹里的发票 PDF 挑出来，按月份归档。”

[本课程观点] 纯聊天模型能给你一段 Python 代码，甚至能解释每行做什么，但它不会去读你的文件夹。Agent 则会：列出目录 → 识别哪些文件是 PDF → 打开每个 PDF 读取文本 → 判断是否为发票、属于哪个月 → 创建月份文件夹 → 移动文件 → 汇报结果。中途它可能发现文件名是乱码，于是改用 PDF 内容判断；也可能发现某个月份文件夹已存在，于是选择合并而不是覆盖。

[本课程观点] 正是这些“中途判断”让 Agent 有用，也让结果不稳定。如果它不知道你们的命名规则、发票判定标准和归档结构，它只能猜。猜错一次，你就要人工返工十次。

[本课程观点] 这个例子值得注意的是中途的判断：文件名乱码时改看内容、目标文件夹已存在时选择合并。每一步判断都依赖环境反馈，而不是一次性计划。Agent 做得好不好，往往取决于它能否在反馈中修正方向。对 Skill 作者来说，这意味着两件事：第一，把容易误判的地方写成明确规则；第二，给出验证结果的方法，让 Agent 知道什么时候该停、什么时候该换方法。只写“整理下载文件夹”五个字，等于把全部判断都交还给模型的通用直觉。

Agent 的能力缺口：不是不会做，是不知道你们的做法

[本课程观点] 模型通常已经具备通用能力：读写文件、写脚本、调用常见库、解释报错。它缺的是专门知识：你们团队的字段命名、某个内部 API 的怪癖、监管要求的措辞、某类文档必须保留的页边距。

[本课程观点] 这些知识有三种常见去处：

  • 每次对话现说：灵活，但重复、易漏，且下次会话就消失。
  • 写进系统提示词：稳定，但会占用每次请求的上下文，技能一多就膨胀。
  • 写成 Skill，按需加载：平时只占一行元数据，相关任务出现时才读全文。这正是 Agent Skills 的设计目标。

[源站] Agent Skills 被定义为“一种轻量、开放的格式，用专门的知识和工作流扩展 AI Agent 的能力”。其核心是一个包含 SKILL.md 的文件夹；该文件至少包含 name 与 description 元数据，以及告诉 Agent 如何完成特定任务的指令。Skill 还可以捆绑脚本、参考材料、模板和其他资源。（来源：home.md）

可以把三者的分工记成一句话：工具给 Agent 手脚，Skill 给 Agent 你们的方法，模型提供通用判断力。[本课程观点]

[本课程观点] 区分“能力缺口”和“知识缺口”很重要。模型不会读某个内部系统，是能力缺口，需要工具；模型能读，但不知道字段含义，是知识缺口，需要 Skill。很多失败案例被误判成模型不够聪明，实际上是它拿到了正确的工具却缺少判断依据。写 Skill 前先问：如果给模型一个完全自由的终端和文件系统，它还会错吗？如果会，缺的多半就是你可以补的知识。

什么样的任务适合写成 Skill

[本课程观点] 不是所有事都值得。一个任务越接近下面这些特征，越适合：

  • 重复出现：每周、每个 PR、每批文件都会遇到。
  • 有隐性知识：新同事要带两周才会，文档里没写全。
  • 有固定产出：报告格式、评审意见结构、文件命名规则相对稳定。
  • 容错成本高：漏一个必填字段、错一个金额，代价明显。
  • 可以被验证：对错有客观标准，能写检查或断言。

[本课程观点] 反过来，“帮我想个名字”“解释这段代码”这类开放、一次性的请求，通常不需要 Skill；模型的通用能力已经够用，写了反而增加维护负担。

[本课程观点] 用这五条做一次快速打分：重复性、隐性知识、固定产出、容错成本、可验证性各一分。四分以上值得先做；两三分可以先写一个很小的版本试运行；一分以下通常不值得。还要排除一种情况：任务虽然重复，但每次都需要人类做价值判断，例如决定裁员名单或对外发布措辞。这类任务可以写成“准备材料、列出选项、标出风险”的技能，但不能让 Agent 代替人做最终决定。

如果你只记住三件事

  1. LLM 只生成文本；Agent 通过“观察—决策—行动”的循环，借助工具真正做事。
  2. Agent 的短板通常不是通用智力，而是缺少你们组织内部的专门知识与流程。
  3. Skill 是把这类知识打包、按需加载的载体；它补的是“怎么做”，不是“能不能做”。

练习

基础

[本课程观点] 判断以下两个任务哪个更适合写成 Skill，并说明理由：（A）把每周销售 CSV 整理成固定格式的周报；（B）解释一段你不熟悉的 Rust 代码。

提示与自检

[本课程观点] A 更合适：周期性、格式固定、有团队规则、可验证。B 通常不需要：一次性、开放、模型通用能力足够。若你只答“A 更常见”而没提可验证性与隐性知识，回去看“什么样的任务适合写成 Skill”。

基础

[本课程观点] 回到本页第一个概念小节，用两三句话说明它解决什么问题，并举一个你工作中会遇到的例子。

提示与自检

[本课程观点] 合格答案要包含“问题—做法—具体场景”三部分；只复述小节标题，或举一个与本页无关的例子，都不算完成。

进阶

[本课程观点] 用你自己的话画出 Agent 循环，并标出“模型”和“运行环境”各自负责哪一步。再指出：如果工具执行失败，循环会怎样继续？

提示与自检

[本课程观点] 模型负责决策与生成工具调用参数；环境负责真正执行并返回结果（成功输出或错误）。失败时结果回灌给模型，模型读取错误信息后决定重试、换方法或停止。若你把“执行”画在模型一侧，说明还没区分生成与执行。

进阶

[本课程观点] 把本页的方法用到你自己的一个真实任务上，写出两条可执行指令和一个别人能照着做的验证方式。

提示与自检

[本课程观点] 两条指令要具体到字段、命令、阈值或判断标准；验证方式必须给出可观察的结果，例如某个文件存在、某条命令退出码为 0、某个字段等于期望值。

挑战

[本课程观点] 回忆一次 Agent 把你交给它的任务做错的经历。把它拆成：它缺的是通用能力、工具，还是你们的专门知识？如果重来一次，你会把哪三条信息写进 Skill？

评分点
  • 完整回应题目中的两个关键要求：2 分
  • 给出可验证的检查、示例或对照：2 分
  • 说明一个取舍、边界或失败情况：1 分

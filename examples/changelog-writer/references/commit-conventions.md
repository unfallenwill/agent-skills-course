# 提交分类约定

## 用户可见

- `feat:`：新能力，归入 Features。
- `fix:`：修复错误行为，归入 Fixes。
- `perf:`：有可验证数据的性能提升，归入 Improvements；无数据则不写。
- `refactor:`：只有改变对外行为或兼容性时才写，否则跳过。

## 默认跳过

`chore:`、`test:`、`docs:`、`ci:`、`style:` 默认不写；若它们改变用户行为（例如文档中的安装步骤变更），按实际影响归类。

## Breaking

提交说明或 PR 描述中出现 `BREAKING CHANGE`、删除接口、修改默认值、重命名字段时，归入 Breaking，并写迁移步骤。

## 不确定时

无法判断是否用户可见：跳过，并在“未覆盖”中列出提交号，不要编造功能描述。
